# BK0010code — Ассемблер для Электроника БК 0010/0011М

Этот скилл содержит полную техническую базу для написания программ на ассемблере PDP-11 для компьютеров Электроника БК 0010 и БК 0011М.

---

## Процессор

- КМ1801ВМ1, совместим с PDP-11
- **НЕТ расширенных наборов:** EIS (MUL, DIV, ASH, ASHC), FIS, FFP, CIS
- Умножение/деление — только программно
- Числа: восьмеричная система по умолчанию (см. раздел PDPy11 о форматах чисел)
- Слова: 16 бит, little-endian

## Регистры

| Регистр | Роль |
|---------|------|
| R0–R5 | Регистры общего назначения |
| R6 (SP) | Указатель стека (растёт вниз) |
| R7 (PC) | Счётчик команд |
| PSW | Слово состояния: N, Z, V, C + приоритет + T-бит |

## Карта памяти БК 0010

| Адреса (восьм.) | Содержимое |
|-----------------|------------|
| `000000–000777` | Системная область: векторы прерываний, системные переменные, стек |
| `001000–037777` | **ОЗУ пользователя** (15.5 Кб) |
| `040000–077777` | **Экранное ОЗУ** (16 Кб) — 512×256 пикс. (Ч/Б) или 256×256 (цвет) |
| `100000–117777` | ПЗУ: МДС — монитор-драйверная система (EMT-диспетчер по адресу `100112`) |
| `120000–137777` | ПЗУ: интерпретатор Бейсик или Фокал |
| `140000–157777` | ПЗУ: Бейсик или резерв |
| `160000–177577` | ПЗУ: Бейсик или МСД (монитор диагностики) |
| `177600–177777` | Системные регистры |

**Режим расширенной памяти (РП):** АР2+СБР → экран сжимается, ОЗУ `001000–067777`, экран `070000–077777`.

## Системные регистры (177600–177777)

### 177660 — Регистр состояния клавиатуры
- Бит 06: маска прерываний от клавиатуры (0=разрешено, 1=запрещено), R/W
- Бит 07: флаг готовности (1=новый код в 177662), только чтение

### 177662 — Регистр данных клавиатуры
- Биты 00–06: 7-битный код нажатой клавиши (без учёта РУС/НР), только чтение
- Код появляется независимо от разрешения прерывания

### 177664 — Регистр смещения (рулон экрана)
- Биты 00–07: номер ТВ-строки начала экрана (при сдвиге рулона), R/W
- Бит 09: 0=режим РП, 1=обычный режим, R/W
- Исходное значение: `330` (адрес экрана = `040000`)

### 177706 — Регистр предустановки таймера (R/W, все 16 бит)
### 177710 — Счётчик таймера (только чтение)
### 177712 — Регистр управления таймером (R/W, биты 00–07)
- Бит 00: режим предустановки (1=стоп+загрузить константу)
- Бит 01: непрерывный счёт (1=не фиксировать переход через 0)
- Бит 02: режим индикации (1=установить бит 07 при переходе через 0)
- Бит 03: однократный счёт (1=остановиться после одного цикла)
- Бит 04: разрешение счёта (1=старт)
- Бит 05: замедление ×4
- Бит 06: замедление ×16 (оба бита 05+06 = ×64)
- Бит 07: флаг индикации перехода через 0
- Единичный период: ~42.9 мкс
- Коды запуска: `20` (×1, макс 2.8с), `120` (×4, 11.3с), `60` (×16, 45с), `160` (×64, 180с)

### 177714 — Порт ввода-вывода (все 16 бит, R/W, **инвертированный!**)
- Запись → регистр вывода; чтение → регистр ввода (разные регистры!)
- Запись дублируется в ячейку памяти 256₈
- Логика инвертирована: запись 0 → на выходе 1

### 177716 — Регистр системных внешних устройств
**Чтение (ввод):**
- Бит 04: данные с ТЛГ-линии
- Бит 05: данные с магнитофона
- Бит 06: индикатор нажатия клавиши (**0=нажата, 1=не нажата** — инверсия!)
- Бит 07: сигнал готовности ТЛГ-линии

**Запись (вывод):**
- Бит 04: передача на ТЛГ-линию
- Бит 05: сигнал на магнитофон / готовность ТЛГ
- Бит 06: **звук** (пьезодинамик + выход МАГНИТОФОН) — чередовать 0/1 для генерации тона
- Бит 07: управление двигателем магнитофона (0=вкл, 1=выкл)
- Биты 08–15: адрес запуска системы (только чтение, содержит `100000`)

## EMT-функции БК 0010

EMT-диспетчер находится по адресу `100112`. Используются **только чётные номера**.
Параметры передаются в регистрах **до** вызова EMT.

| EMT | Функция | Вход | Выход | Сохр. R |
|-----|---------|------|-------|---------|
| `EMT 4` | Инициализация драйвера клавиатуры | — | — | кроме R0 |
| `EMT 6` | Ввод символа с клавиатуры (ждёт) | — | R0=код | — |
| `EMT 10` | Ввод строки с клавиатуры | R1=адрес буфера; R2=длина(мл.байт)+ограничитель(ст.байт) | R1=след.адрес, R2=остаток | — |
| `EMT 12` | Установка программируемого ключа | R0=номер(1–12), R1=адрес текста (1-й байт=длина) | — | кроме R0 |
| `EMT 14` | Инициализация всех драйверов (перезапуск) | — | — | кроме R0–R4 |
| `EMT 16` | Вывод символа на экран | R0(мл.байт)=код символа или команды | — | все |
| `EMT 20` | Вывод строки на экран | R1=адрес, R2=длина+ограничитель | — | — |
| `EMT 22` | Запись символа в служебную строку | R0=код (0=очистить), R1=позиция | — | — |
| `EMT 24` | Установка курсора | R1=X, R2=Y | — | — |
| `EMT 26` | Чтение координат курсора | — | R1=X, R2=Y | — |
| `EMT 30` | Рисование точки | R1=X, R2=Y, R0=1(нарисовать)/0(стереть) | — | — |
| `EMT 32` | Рисование вектора | R1=X конца, R2=Y конца, R0=1/0 | — | — |
| `EMT 34` | Чтение слова состояния дисплея (ССД) | — | R0=ССД | — |

### Управляющие коды для EMT 16 / EMT 20

Все значения восьмеричные. Коды принимаются в мл. байте R0 (EMT 16) или в потоке строки (EMT 20).

#### Управляющие коды (0–177)

| Код | Источник | Назначение |
|-----|----------|-----------|
| `3` | КТ | Код конца текста — нет действия (в ИНД СУ: инв. С) |
| `7` | ЗВ | Звуковой сигнал (BEL); в БЛОК РЕД — блокируется |
| `10` | ← | Перевод курсора влево |
| `12` | ВВОД | Перевод строки (перевод курсора в начало следующей строки) |
| `14` | СБР | Очистка экрана и перевод курсора в начало (в БЛОК РЕД: блокируется) |
| `22` | СУ/Р | Исходная установка курсора (HOME) |
| `23` | ВС | Перемещение нижней части экрана на одну строку вверх |
| `24` | СУ/Т | Перемещение нижней части экрана на одну строку вниз |
| `25` | СУ/У | Перемещение курсора в начало следующей строки |
| `26` | СТИ | Удалить символ: правая часть строки сдвигается влево |
| `27` | ВСТ | Вставить: правая часть строки сдвигается вправо |
| `30` | ЗАБОЙ | Удалить последний символ |
| `31` | → | Перевод курсора вправо |
| `32` | ↑ | Перевод курсора вверх |
| `33` | ↓ | Перевод курсора вниз |
| `34` | СУ/Э | Диагональ ↖ |
| `35` | СУ/Ш | Диагональ ↗ |
| `36` | СУ/Ч | Диагональ ↘ |
| `37` | СУ/Ъ | Диагональ ↙ |
| `231` | СТИ→ | Очистка правой от курсора части строки |

#### Специальные коды режимов (200+)

Коды `202`, `204`, `232`, `233`, `235`, `236` при вводе с клавиатуры **не поступают в программу** — перехватываются драйвером клавиатуры напрямую. Все остальные из списка ниже поступают в программу. Любой код можно послать программно через EMT 16/20.

| Код | Клавиша | Назначение |
|-----|---------|-----------|
| `202` | ИНД СУ | Режим индикации управляющих символов (toggle). В этом режиме управляющие коды рисуются инверсными лат. буквами |
| `204` | БЛОК РЕД | Блокировка редактирования (toggle). Редактирующие коды отображаются, не выполняются |
| `214` | АР2+СБР | **Режим расширенной памяти (РП)** — освобождает 12 Кб; ОЗУ 0–67777 (28 Кб), экран 4 Кб (служебная строка + 4 строки). Признак — индикатор в служебной строке. Сброс — повторная подача кода |
| `220` | ШАГ | Код клавиши ШАГ (= 0 в потоке ввода) |
| `221` | АР2+Шфт+1 | Цвет текста: **Красный** (самый яркий) |
| `222` | АР2+Шфт+2 | Цвет текста: **Зелёный** |
| `223` | АР2+Шфт+3 | Цвет текста: **Синий** |
| `224` | АР2+Шфт+4 | Цвет текста: **Чёрный** (фоновый) |
| `225` | СУ+АР2+У | **ГРАФ** — режим текстовой графики (toggle) |
| `226` | СУ+АР2+Ж | **ЗАП** — режим записи точек в ГРАФ (toggle) |
| `227` | СУ+АР2+В | **СТИР** — режим стирания точек в ГРАФ (toggle) |
| `230` | АР2+ЗАБОЙ | Включение режима редактирования |
| `231` | СТИ→ | Сброс правой части строки |
| `232` | АР2+: | **Курсор** — гашение/показ курсора (toggle). Ускоряет вывод |
| `233` | АР2+; | **32/64** — переключение ширины символа (32 или 64 в строке) |
| `234` | АР2+, | **Инв.С** — инверсия символов (toggle) |
| `235` | АР2+- | **Инв.Э** — инверсия экрана (toggle; не поступает в программу с клавиатуры) |
| `236` | АР2+. | **УСТ.ИНД** — очистка служебной строки + перестройка индикаторов |
| `237` | АР2+/ | **ПОДЧ** — подчёркивание символов (toggle) |

Цвета работают только в режиме 32 символа в строке с цветным ТВ.

#### Режим текстовой графики (ГРАФ)

После `225` (ГРАФ) курсор становится графическим (крест). Перемещать курсор можно кодами стрелок (`10`, `31`–`37`). Линия рисуется только в режиме ЗАП (`226`), стирается в СТИР (`227`).

Эффективный способ рисования линии — одним словом через EMT 16:
- Мл. байт R0 = код направления (стрелка)
- Ст. байт R0 = длина линии − 1 (0 = одна точка, 255 = 256 точек)

Выход из ГРАФ: повторный `225`.

#### Слово состояния дисплея (EMT 34 → R0)

| Бит | Режим |
|-----|-------|
| 0 | 32 символа в строке |
| 1 | Инверсия фона |
| 2 | Режим расширенной памяти (РП) |
| 3 | Русский регистр |
| 4 | Подчёркивание символа |
| 5 | Инверсия символа |
| 6 | Индикация СУ |
| 7 | Блокировка редактирования |
| 8 | Текстовая графика (ГРАФ) |
| 9 | Режим записи в ГРАФ |
| 10 | Режим стирания в ГРАФ |
| 11 | 32 символа в служебной строке |
| 12 | Подчёркивание в служебной строке |
| 13 | Инверсия символа в служебной строке |
| 14 | Гашение курсора |

Ячейки `000040`–`000056` (PRCW, PRINF, PRRP …) отражают те же биты побайтно: `000` = выкл, `377` = вкл (кроме PRRUS: `200` = русский).

#### Координатные ограничения EMT 30/32

- Y: 0–239 (240 строк)
- X в режиме 64 символа: 0–511 (512 точек)
- X в режиме 32 символа: 0–255 (256 точек)
- EMT 32: если координата конца вектора выходит за экран, рисуется видимая часть, координаты запоминаются

#### EMT 22 — служебная строка

R0=код (0=очистить всю строку), R1=позиция (0…). Поле индикаторов занимает правые ≤24 позиции служебной строки. Строка очищается также кодами `236` и `214`.

## EMT 36 — Магнитофон

```
R1 = адрес блока параметров (чётный адрес)
EMT 36
```

Стандартная область для блока: `320`–`371` (только если стек не войдёт в конфликт).

После чтения: адрес массива → ячейка `264`, длина → ячейка `266`.

**Формат блока параметров (байты десятичные):**

| Байты | Содержимое |
|-------|-----------|
| 0 | Команда |
| 1 | Ответ (заполняется драйвером) |
| 2–3 | Адрес массива (чтение: куда читать; 0 = по адресу из заголовка) |
| 4–5 | Длина массива в байтах (только запись) |
| 6–25 | Имя массива (запись: задаётся; чтение: искомое имя) |
| 22–23 | Адрес текущего (прочитанного) массива |
| 24–25 | Длина текущего массива |
| 26–41 | Имя текущего массива |

**Команды (байт 0):**

| Код | Команда |
|-----|---------|
| 0 | Остановить двигатель |
| 1 | Запустить двигатель |
| 2 | Записать массив |
| 3 | Читать массив (с проверкой имени и CRC) |
| 4 | Фиктивное чтение (без записи в ОЗУ и без CRC) |

**Ответы (байт 1):**

| Код | Смысл |
|-----|-------|
| 0 | Успех |
| 1 | Имя не совпало (двигатель не остановлен — продолжить поиск без изменения блока) |
| 2 | Ошибка CRC |
| 4 | Прервано клавишей СТОП |

Клавиша СТОП прерывает запись/чтение в любой момент.

## Переключение страниц памяти

**ВАЖНО: БК 0010 без СМК — переключения страниц НЕТ.**

Страницы: **0** = ОЗУ с ОС (MKDOS/ANDOS), **1–5** = свободные.
Постоянно закреплены: `000000` (программа), `040000` (экран).
Номер страницы → R0, затем `CALL @MemPage`.

```asm
DetectSystem:
        CMPB @#177717,#300      ; Z=1 → БК 0011, Z=0 → БК 0010
        BEQ 2
        CMP @#167776,#176200    ; проверка СМК (176200=СМК-64, 176600=СМК-128)
        BHIS 1
            MOV #NoMem,MemPage  ; БК 0010 без СМК
            RET
1:      MOV #Switch10,MemPage   ; БК 0010 + СМК
2:      RET
MemPage: .WORD Switch11

Switch11:                       ; БК 0011
        ASL R0
        MOV Mem11(R0),@#177716
        RET
Mem11:  .WORD 16000,14000,15000,15400,17400,16400

Switch10:                       ; БК 0010 + СМК
        ASL R0
        MOV #6,@#177130
        MOV MemSMK(R0),@#177130
        MOV #0,@#177130
NoMem:  RET
MemSMK: .WORD 60,2060,160,2160,64,2064
```

Использование: `CALL DetectSystem` (один раз), затем `MOV #N,R0 / CALL @MemPage`.

## Джойстик и клавиатура

### Регистры
- `177714` — порт джойстика (и COVOX на выход)
- `177662` — код последней нажатой клавиши (только чтение, биты 0–6)
- `177716` бит 06 — флаг нажатия (`#100`): **0=нажата, 1=не нажата** (инверсия!)

**ВАЖНО:** При прямом чтении регистров клавиатуры — обязательно `MTPS #340` в начале программы. Иначе системный обработчик прерывания клавиатуры успеет считать и сбросить регистр раньше вашего кода. При заблокированных прерываниях нельзя использовать `WAIT` — заменять на цикл задержки.

### Таблица кодов управления (все значения восьмеричные)

| # | Направление | CodesJ (бит порта 177714) | CodesK (код клавиши из 177662) |
|---|-------------|---------------------------|-------------------------------|
| 1 | Влево       | `10`                      | `10`                          |
| 2 | Вправо      | `2`                       | `31`                          |
| 3 | Вверх       | `1`                       | `32`                          |
| 4 | Вниз        | `4`                       | `33`                          |
| 5 | Кнопка L    | `40`                      | `40` (пробел)                 |
| 6 | Кнопка R    | `100`                     | `40` (пробел)                 |

Диагонали (жёлтые клавиши первой плоской клавиатуры БК 0010): `34`=↖, `35`=↗, `36`=↘, `37`=↙.

Все числа восьмеричные. Точка после числа (например `31.`) означает десятичную запись и даёт неверный код.

### Простая процедура JOY (одно событие)

Возвращает R0 = номер события (1=влево, 2=вправо, 3=вверх, 4=вниз, 5=L, 6=R) или 0 если ничего не нажато. Использует только регистр R0.

```asm
JOY:    BIT #100,@#177716       ; клавиша нажата? (0=нажата)
        BNE 2
        MOV #CodesK-CodesJ,R0   ; R0 = количество элементов (6)
1:        CMPB CodesK-1(R0),@#177662  ; сравнить код клавиши
          BEQ 4
        SOB R0,1
2:      MOV #CodesK-CodesJ,R0
3:        BITB CodesJ-1(R0),@#177714  ; сравнить биты джойстика
          BNE 4
        SOB R0,3
4:      RET                     ; R0 = событие (0 если ничего)

CodesJ: .BYTE 10,2,1,4,40,100
CodesK: .BYTE 10,31,32,33,40,40
```

### Процедура JOY с буфером событий (несколько одновременных)

Заполняет буфер Events всеми одновременно активными событиями (джойстик поддерживает несколько кнопок одновременно). Список завершается нулём. Использует регистры R0–R3.

```asm
JOY:    MOV #CodesK-CodesJ,R0   ; R0 = 12 (6 слов × 2 байта)
        MOV #Events,R1           ; указатель на буфер событий
        MOV @#177714,R2          ; читаем порт джойстика
        BIC JoyMask,R2           ; убираем повреждённые биты
        MOV @#177662,R3          ; читаем код клавиши
        BIT #100,@#177716        ; клавиша нажата?
        BEQ 1
        NEG R3                   ; нет — сделать R3 отрицательным
1:        TST R3                 ; клавиша нажата?
          BMI 2                  ; нет (R3<0) — пропустить проверку клавиатуры
          CMP CodesK-2(R0),R3    ; сравнить с таблицей клавиатуры
          BEQ 3
2:        BIT CodesJ-2(R0),R2   ; сравнить с таблицей джойстика
          BEQ 4
3:        MOVB R0,(R1)           ; сохранить R0 в буфер
          ASRB (R1)+             ; разделить на 2 → номер события; R1++
4:      DEC R0
        SOB R0,1                 ; шаг -2 за итерацию (DEC + SOB)
        CLRB (R1)                ; завершить список нулём
        RET

CodesJ:  .WORD 10,2,1,4,40,100
CodesK:  .WORD 10,31,32,33,40,40
Events:  .BLKB 6
JoyMask: .WORD 0                 ; маска повреждённых битов порта
```

**Трюк `DEC R0; SOB R0,1`**: уменьшает R0 на 2 за итерацию, шагая по словам массива. При R0=12,10,8,6,4,2 — `ASRB` превращает их в события 6,5,4,3,2,1.

**`NEG R3` / `TST R3; BMI 2`**: если клавиша не нажата, R3 становится отрицательным, и проверка по CodesK пропускается. Особый случай: код клавиши ШАГ = 0, `NEG 0 = 0` — тогда вместо `NEG` лучше использовать `COM`.

### Обнаружение и маскировка повреждённых битов порта

Повреждённые биты в микросхемах 589ИР12 параллельного порта — не редкость. Они всегда читаются как 1 и имитируют нажатие джойстика. Перед игрой — проверить порт:

```asm
TestPort:
        CLR R0                   ; 65536 попыток
1:        TST @#177714           ; порт = 0?
          BEQ PortOK
        SOB R0,1
        ; порт не обнулился — вывести "PLEASE RELEASE JOYSTICK" и повторить
        ; если со второй попытки тоже не 0:
        MOV @#177714,JoyMask     ; сохранить повреждённые биты в маску
PortOK:
```

После этого во всех процедурах опроса джойстика: `BIC JoyMask,R2` перед сравнением с CodesJ. Если порт исправен, JoyMask = 0 и BIC ничего не меняет. При переназначении управления сравнивать не с нулём, а с JoyMask:

```asm
1:      CMP @#177714,JoyMask     ; ждать отпускания джойстика
        BNE 1
2:      CMP @#177714,JoyMask     ; ждать нажатия
        BEQ 2
```

### Преобразование числа в десятичную строку (14 слов — оптимальный алгоритм)

Строка строится **справа налево** — нулевой терминатор пишется первым, цифры заполняются в обратном порядке. Стек для разворота цифр не нужен. После возврата **R1 указывает на первый символ** строки.

```asm
; Вход: R0 = число (0..65535), R1 = адрес ПОСЛЕ буфера (метка в конце)
; Выход: R1 → первая цифра нуль-терминированной строки
; Портит: R0, R1, R5
ITOA:   CLRB -(R1)              ; нулевой терминатор (в конце буфера)
1:      CLR R5
2:      INC R5
        SUB #10.,R0             ; вычитаем 10, пока R0 >= 0
        BHIS 2
        ADD #58.,R0             ; компенсация: +10 (откат) + 48 ('0' ASCII)
        MOVB R0,-(R1)           ; записываем цифру справа
        MOV R5,R0               ; R5 = частное+1 → R0
        SOB R0,1                ; SOB декрементирует: R0 = частное; ветвь если ≠ 0
        RET

        .BLKB 5
ITOA_END:                       ; передавать R1=#ITOA_END; буфер — 5 цифр + нуль = 6 байт
```

**Ключевые приёмы:**
- `CLR R5` вместо `MOV #-1,R5` — R5 выходит на 1 больше частного, SOB автоматически компенсирует
- `ADD #58.` = `+10` (откат лишнего вычитания) + `+48` (ASCII '0') — два действия одной командой
- Заполнение справа налево — не нужен стек для обращения порядка цифр
- `SOB R0,1` вместо `DEC R0 / BNE 1` — одно слово вместо двух (с учётом, что R0 = частное+1)

## Ассемблер PDPy11 — синтаксис и возможности

Используемый ассемблер: **PDPy11** (purplesyringa/PDPy11).

### Форматы чисел

| Запись | Система |
|--------|---------|
| `1234` | **Восьмеричная** (по умолчанию) |
| `1234.` | Десятичная (суффикс `.`) |
| `0b101010` | Двоичная |
| `0o1234` | Восьмеричная (явная) |
| `0x1234` | Шестнадцатеричная |

Директива `decimalnumbers ON` переключает умолчание на десятичную систему.

### Арифметические выражения

В режиме pdpy11 (умолчание) поддерживаются выражения со скобками:

```
A = (B + C / 2) * 2 + 7 * 3
```

Операторы (по возрастанию приоритета): `|` `^` `&` `<<` `>>` `+` `-` `*` `/` `%`

В режиме `.SYNTAX pdp11asm` — только `+ - * /`, выполняются слева направо без приоритета.

### Локальные метки

Числовые метки (`1:`, `2:` ...) **уникальны в пределах файла** и **видны только между соседними глобальными (именованными) метками**. **Суффиксы `f`/`b` не поддерживаются** — писать просто `BR 1`, не `BR 1f`.

Если между командой `BEQ 42` и меткой `42:` стоит именованная метка (`DMS_LEFT:` и т.п.), ассемблер не находит `42:` и выдаёт ошибку компиляции. Решение — переименовать целевую числовую метку в глобальную (`M42:`).

Поведение зависит от команды:

| Команда | Значение |
|---------|----------|
| `BR 1` | переход на метку `1:` |
| `BR 1 - 2` | адрес метки `1:` минус 2 байта |
| `BR (1)` | переход на **глобальный адрес** 1 (не метка!) |
| `BR (1:)` | переход на метку `1:` в выражении |
| `JMP 1` | переход на **глобальный адрес** 1 |
| `JMP (1:)` | переход на метку `1:` |

Вывод: в `BR` голое число = метка; в `JMP` голое число = абсолютный адрес.

### Адрес загрузки

Директивы `ORG`, `.LINK`, `.LA` устанавливают адрес компоновки. **По умолчанию — 1000**, поэтому `.= 01000` в начале программы писать **не нужно**.

### Директивы данных

| Директива | Действие |
|-----------|----------|
| `.BYTE n` / `.DB n` | записать байт |
| `.WORD n` / `.DW n` | записать слово (2 байта) |
| `.BLKB n` / `.DS n` | n нулевых байт |
| `.BLKW n` | n нулевых слов |
| `.ASCII /str/` | строка без терминатора |
| `.ASCIZ /str/` | строка + нулевой байт |
| `.EVEN` | выровнять PC на чётный адрес |
| `ALIGN n` | выровнять PC кратно n |

### Директивы управления компиляцией

| Директива | Действие |
|-----------|----------|
| `.END` / `END` | конец файла |
| `.INCLUDE /file/` | включить файл |
| `.ONCE` | включить файл не более одного раза (для библиотек) |
| `.REPEAT n { ... }` | повторить блок n раз |
| `.SYNTAX pdpy11` | режим pdpy11 (умолчание) |
| `.SYNTAX pdp11asm` | режим совместимости с pdp11asm |
| `decimalnumbers ON/OFF` | умолчание: десятичная / восьмеричная |
| `insert_file /file/` | включить файл как бинарные данные |

### Форматы выходного файла

| Директива в исходнике | Формат |
|-----------------------|--------|
| `make_bin` / `make_bk0010_rom` | `.bin` с заголовком (стандарт БК) |
| `make_raw` | без заголовка |
| `make_sav` | `.sav` |
| `make_turbo_wav` | WAV турбо-загрузки |
| `make_wav` | WAV стандартной загрузки |

Имя файла `~speaker` — воспроизвести WAV через динамики прямо при компиляции.

### Запуск компилятора

```
pdpy11 prog.mac              # → prog.bin
pdpy11 prog.mac --raw        # → prog (без заголовка)
pdpy11 prog.mac --sav        # → prog.sav
pdpy11 prog.mac -o out.bin   # явное имя выходного файла
pdpy11 prog.mac --link 2000  # адрес загрузки (если нет .LINK в файле)
pdpy11 prog.mac --lst        # генерировать листинг .lst
pdpy11 prog.mac --syntax pdp11asm  # режим совместимости
pdpy11 --project ./dir       # компилировать весь проект
```

## Размеры инструкций и диапазоны переходов

### Размер инструкций в словах

Каждая инструкция занимает **1 слово базово**, плюс по **+1 слово** на каждый операнд, использующий расширенную адресацию:

| Режим адресации | Пример | Доп. слов |
|-----------------|--------|-----------|
| Регистровый | `R0` | 0 |
| Косвенный регистровый | `(R0)` | 0 |
| Автоинкремент | `(R0)+` | 0 |
| Автодекремент | `-(R0)` | 0 |
| Автоинкремент косвенный | `@(R0)+` | 0 |
| Автодекремент косвенный | `@-(R0)` | 0 |
| Непосредственный | `#1234` | +1 |
| Абсолютный | `@#177716` | +1 |
| Относительный (метка) | `LABEL` | +1 |
| Относительный косвенный | `@LABEL` | +1 |
| Индексный | `2(R0)` | +1 |
| Индексный косвенный | `@2(R0)` | +1 |

**Примеры:**
- `CLR R0` → 1 слово
- `CLR (R0)+` → 1 слово
- `CLR #5` → 2 слова (непосредственный)
- `CLR @#177716` → 2 слова (абсолютный)
- `MOV #1234,(R2)+` → 2 слова (непосредственный src; автоинкремент dst не добавляет слов)
- `MOV #1234,2(R2)` → 3 слова (непосредственный src + индексный dst)
- `MOV @#177662,R0` → 2 слова
- `SOB R0,LOOP` → 1 слово (смещение закодировано в самой инструкции)
- `BNE LABEL` → 1 слово (смещение закодировано в самой инструкции)
- `JMP LABEL` → 2 слова (относительный режим: JMP + слово смещения)
- `EMT 24` → 1 слово

### Диапазоны коротких переходов

**Все ветвления с 8-битным смещением (±127 слов = ±254 байта):**
`BR`, `BNE`, `BEQ`, `BPL`, `BMI`, `BVC`, `BVS`, `BCC`/`BHIS`, `BCS`/`BLO`,
`BGE`, `BLT`, `BGT`, `BLE`, `BHI`, `BLOS`

**SOB — только назад, 6-битное смещение (0..63 слова = 0..126 байт)**

### Обязательное правило

**При написании любого цикла или перехода — подсчитать сумму слов всех инструкций между командой перехода и меткой. Если сумма превышает лимит — использовать длинный переход.**

Для SOB лимит 63 слова; для условных ветвлений лимит 127 слов (в каждую сторону).

### Паттерн длинного условного перехода

`JNE`, `JEQ` и аналогов в PDP-11 **не существует**. `JMP 30` воспринимается как переход на адрес памяти 30 (восьм.), а не метку. Использовать именованные метки:

```asm
; Вместо: SOB R4, BIGLOOP  (слишком далеко)
        DEC R4
        BEQ 1           ; если ноль — выход из цикла
        JMP BIGLOOP     ; иначе — на метку (полный адрес)
1:      ...             ; сюда после окончания цикла
```

```asm
; Вместо: BNE FARLABEL  (слишком далеко)
        BEQ 1           ; инвертируем условие
        JMP FARLABEL
1:      ...
```

## Важные нюансы

1. **Порт 177714 инвертирован**: читать и писать — разные регистры; запись 0 → на линии 1.
2. **Бит нажатия клавиши в 177716**: 0 = нажата (не 1!).
3. **EMT только чётные номера** на БК 0010.
4. **R7 = PC**: можно адресовать через PC — это даёт режимы `#n` (immediate), `a` (relative) и т.д.
5. **MOVB знакорасширяет** в биты 8–15 при записи в регистр.
6. **XOR** — первый операнд только регистр, не непосредственное значение.
7. **SOB** — декремент без влияния на флаги; переход только назад; смещение 6 бит (0..63 слов).
8. **Стек**: SP указывает на последнее записанное слово; `-(SP)` = push, `(SP)+` = pop.
9. **БК 0010 без СМК**: нет переключения страниц памяти; только 15.5 Кб ОЗУ + 16 Кб видео.
10. **Диапазоны переходов**: всегда подсчитывать слова между командой перехода и меткой; если превышает лимит — использовать длинный переход (см. раздел «Размеры инструкций»).

### Генератор псевдослучайных чисел (Random)

Два 16-битных seed'а, смешиваются через ROR/ROL/SWAB/XOR. Результат в диапазоне -64..63.

```asm
; Выход: R1 = случайное число -64..63
;        R2 = второй случайный поток (полные 16 бит, не ограничен)
; Портит: R0
Random: MOV  #Seed1, R0
        MOV  (R0)+, R1      ; R1 = Seed1
        MOV  (R0), R2       ; R2 = Seed2
        ROR  R1
        ROL  R2
        SWAB R2
        XOR  R2, R1
        MOV  R2, (R0)       ; сохранить Seed2
        MOV  R1, -(R0)      ; сохранить Seed1
        RET
Seed1:  .WORD 173451
Seed2:  .WORD 54102
```

### Быстрое умножение через таблицу квадратов (Mul8bit)

Использует тождество: `a*b = ((a+b)² - (a-b)²) / 4`.
Таблица `Q` хранит `i²/16` для i в диапазоне -255..255. Индексируется как **байтовое смещение** (т.е. `Q(R)` при R = значение как слово-смещение). Метка `Q` должна быть посередине таблицы (1000 байт до и после).

```asm
; Построить таблицу один раз при запуске:
BuildMulTable:
        MOV  #255., R0
        MTPS R0             ; запретить прерывания на время построения
1:      MOV  R0, R2
        CLR  R1
2:      ADD  R0, R1         ; R1 = R0 * R0
        SOB  R2, 2
        ROR  R1             ; R1 = R0² / 16
        ASR  R1
        ASR  R1
        ASR  R1
        MOV  R0, R2
        ASL  R2             ; байтовый индекс = значение * 2
        MOV  R1, Q(R2)      ; Q[+R0] = R0²/16
        NEG  R2
        MOV  R1, Q(R2)      ; Q[-R0] = R0²/16
        SOB  R0, 1
        CLR  Q              ; Q[0] = 0

; Умножение:
; Вход:  R1 = a,  R2 = b  (значения как байтовые смещения, т.е. в единицах ×2)
; Выход: R2 = a*b/4
; Портит: R0
Mul8bit:
        MOV  R2, R0
        SUB  R1, R0         ; R0 = b - a
        ADD  R1, R2         ; R2 = a + b
        MOV  Q(R2), R2      ; R2 = (a+b)²/16
        SUB  Q(R0), R2      ; R2 = ((a+b)² - (b-a)²)/16 = a*b/4
        RET
```

Результат в 4 раза меньше точного произведения — это компенсируется масштабом данных.

### Счётчик кадров через самомодифицирующийся код

`SUB #N, #0` записывает результат обратно в свой же операнд (immediate как dst — пишет в поток команд). При N делящем 65536 ровно — выполняется 65536/N раз до обнуления.

```asm
; Пример: цикл на 16 итераций (65536 / 010000 = 16)
MainLoop:
        ; ... тело кадра ...
        SUB  #010000, #0    ; уменьшает встроенный счётчик
        BNE  MainLoop       ; Z=1 когда счётчик обнулится
```

Полезно для демо: задаёт длительность сцены без отдельной переменной.

### Предвычисленные таблицы для рисования точек

Для скорости: XTable и YTable хранят готовые части адреса и маску бита — чтобы рисование точки занимало 3 команды.

```asm
; Построить таблицы (по 400₈ = 256 элементов):
; YTable[y] = базовый адрес строки экрана (040000 + y*100₈)
; XTable[x] = байтовое смещение внутри строки
; DotMask[x] = битовая маска пикселя
;
; Центр таблиц = середина (400₈ = 256 слов), индексируется со знаком:
; MOV YTable+400(R2), R2   ; Y со знаком → адрес строки
; ADD XTable+400(R4), R2   ; X со знаком → смещение
; MOV DotMask+400(R4), R4  ; X со знаком → маска
; BIS R4, (R2)             ; нарисовать точку

; Стереть точку (маска и адрес сохранены в буфере звёзд):
; BIC SavedMask, @SavedAddr
```

Индексирование от середины таблицы (`+400₈`) позволяет использовать знаковые координаты без проверок.

### Компактная очистка видеопамяти через CLRB с индексным режимом

Очищает все 16 КБ экранного ОЗУ (040000–077777) тремя инструкциями, используя `CLRB base(R0)` с декрементом через SOB:

```asm
        MOV  #37777, R0
CLS:    CLRB 37777(R0)      ; адрес = R0 + 37777: от 077776 до 040000
        SOB  R0, CLS
```

При R0=37777 чистит адрес 077776, при R0=1 — адрес 040000. Последний байт (077777) остаётся, но для большинства задач это несущественно. Для полной очистки использовать вариант из раздела «Типовые шаблоны» (CLR словами).

### Двойной экранный буфер (фоновый буфер)

Для бесшовного движения спрайтов: буфер в ОЗУ зеркалит содержимое экрана. При отрисовке спрайт накладывается поверх данных буфера (BIC маска, BIS пиксели), результат пишется на экран. Фон восстанавливается не очисткой, а чтением из буфера.

```asm
; Схема:
; R2 → адрес на экране    (040000+...)
; R3 → адрес в буфере     (R2 - 034000 = 004000+...)

        MOV  (R3)+, R5      ; взять пиксели фона из буфера
        BIC  (R4)+, R5      ; применить маску спрайта
        BIS  (R1)+, R5      ; наложить пиксели спрайта
        MOV  R5, (R2)+      ; записать результат на экран
```

Буфер заполняется при инициализации (например, случайным фоном), после чего не изменяется — экран всегда восстанавливается из него.

### WAIT — ожидание прерывания (vsync-синхронизация)

Команда `WAIT` останавливает процессор до прихода любого прерывания. Используется для синхронизации с вертикальным гасящим импульсом (vsync):

```asm
        MOV  #VSYNC, @#100  ; установить обработчик прерывания таймера
        MOV  #10.*400, @#PALETTE  ; запустить таймер (код без цвета = старт)
        ...
LOOP:   ; отрисовка кадра
        WAIT                ; ждать vsync-прерывания
        BR   LOOP

VSYNC:  RTI                 ; просто выйти из прерывания
```

Вектор таймера/vsync — адрес 000100. `RTI` возвращает управление после `WAIT`.

### Динамическая генерация подпрограмм

Шаблон подпрограммы копируется в ОЗУ несколько раз (по числу строк спрайта), создавая развёрнутый цикл без накладных расходов на ветвления. В шаблоне `HALT` (код 0) служит маркером конца блока при копировании:

```asm
; Копирование HEIGHT копий шаблона PROC в область DRAW:
        MOV  #HEIGHT, R5
1:      MOV  #PROC, R1      ; R1 → шаблон
2:          MOV  (R1)+, (R2)+   ; копировать слово
            BNE  2              ; пока не HALT (000)
            TST  -(R2)          ; откатиться назад на HALT
        SOB  R5, 1
        MOV  (R1)+, -(R2)   ; слово аргумента JMP
        MOV  (R1)+, -(R2)   ; опкод JMP @# (137₈) — в обратном порядке

; Шаблон заканчивается так:
PROC:   ; ... инструкции тела строки ...
        ADD  R0, R2         ; перейти к следующей строке экрана
        ADD  R0, R3         ; и в буфере
        HALT                ; 000 — маркер конца блока
        .WORD NEXT, 137     ; JMP @#NEXT (аргумент и опкод в обратном порядке)
```

`BNE 2` останавливается на `HALT` (000 = нулевое слово), `TST -(R2)` откатывает R2 назад, затем поверх `HALT` записывается `JMP @#NEXT`.

### Обработка чётных и нечётных адресов при рисовании спрайта

Если X-координата нечётная, спрайт выровнен по нечётному байту — крайние байты обрабатываются через MOVB, средние слова — через MOV:

```asm
PROC_EVEN:                  ; спрайт на чётном адресе — только MOV
        MOV  (R3)+, R5      ; фон (слово)
        BIC  (R4)+, R5
        BIS  (R1)+, R5
        MOV  R5, (R2)+

PROC_ODD:                   ; спрайт на нечётном адресе
        MOVB (R3)+, R5      ; первый байт — MOVB
        BICB (R4)+, R5
        BISB (R1)+, R5
        MOVB R5, (R2)+
        MOV  (R3)+, R5      ; средние слова — MOV
        BIC  (R4)+, R5
        BIS  (R1)+, R5
        MOV  R5, (R2)+
        MOVB (R3)+, R5      ; последний байт — MOVB
        BICB (R4)+, R5
        BISB (R1)+, R5
        MOVB R5, (R2)+
```

Таблицы TABLE1/TABLE2 выбирают нужный спрайт и нужную подпрограмму в зависимости от X & 3.

### ROLB — побайтовый сдвиг с переносом между байтами

`ROLB` сдвигает байт влево через флаг C. Позволяет сдвигать спрайт на 1 пиксель с переносом в соседний байт:

```asm
        CLR  R5
        ROLB SIZE(R1)       ; сдвиг байта спрайта влево, вынос в C
        ROLB R5             ; перенесённый бит → в R5
        ROLB SIZE(R1)       ; ещё один сдвиг
        ROLB R5
        BISB R5, 1+SIZE(R1) ; вписать вынесенные биты в следующий байт
```

### DDA-счётчик частоты через ADD (PC)+,(PC)+

Аккумулятор и шаг хранятся прямо в потоке команд как два слова после инструкции. `ADD (PC)+,(PC)+` читает шаг через первый авто-инкрементный операнд и прибавляет его к аккумулятору через второй. Перенос из суммы попадает в `ADC Rn` — именно он продвигает указатель на сэмпл:

```asm
        ADD  (PC)+, (PC)+
Ch1:    .WORD 1, 1          ; [шаг, аккумулятор] — оба изменяемы
        ADC  R3             ; если перенос — продвинуть указатель сэмпла
```

Запись ноты: `MOV #freq, Ch1` меняет шаг. Запись образца: `MOV #addr, R3`. Схема работает без дополнительных регистров.

### SP как указатель на порт вывода (COVOX)

Освобождает регистр: SP указывает на порт, вывод — одной командой:

```asm
        MOV  #COVOX, SP     ; один раз при инициализации
        ...
        MOVB R1, (SP)       ; вывод байта на COVOX — не трогает другие регистры
```

Стек при этом не используется (прерывания запрещены через `MTPS #340`).

### TST (SP)+ — нелокальный выход из подпрограммы

Выбрасывает адрес возврата из стека, превращая `JMP` в возврат из вызывающей функции. Аналог исключения — прыжок к обработчику ошибки минуя нормальный путь возврата:

```asm
        CALL Foo
        ; ... нормальное продолжение ...

Foo:    ; ...
        BCC  1
            TST  (SP)+      ; выбросить свой адрес возврата
            MOV  #ErrMsg, R1
            JMP  Error      ; уйти в обработчик ошибки, не возвращаясь в Foo
1:      RET
```

### SOB R2, . — пустой цикл задержки на месте

Самый короткий вариант задержки: одна инструкция, ветвится на себя:

```asm
        MOV  #N, R2
        SOB  R2, .          ; . = текущий адрес, крутится N раз
```

### INC PC — пропуск следующей инструкции

`INC PC` сдвигает PC на 1, в результате следующая 2-байтная инструкция пропускается (CPU читает слово со сдвигом на 1 байт, получая «мусорную» инструкцию-заглушку). Применяется для однократного пропуска ветвления:

```asm
        MOV  #55., R4
        INC  PC             ; на втором проходе — пропустить BR 5
        BR   5              ; на первом проходе — повторить цикл
        RET                 ; на втором проходе — выйти
```

### Переменные прямо в потоке команд

`MOV (PC)+, Rn` с меткой на следующем `.WORD` — загрузка значения и одновременно метка для его изменения:

```asm
        MOV  (PC)+, R1
Addr:   .WORD Data          ; и операнд инструкции, и именованная переменная
        ...
```

### Копирование кода до нулевого слова (HALT как маркер)

`HALT` имеет код 0 — нулевое слово. `BNE` в цикле копирования останавливается на нём:

```asm
CopyPlayer:
        MOV  #Low, R5       ; адрес назначения
1:      MOV  (R4)+, (R5)+
        BNE  1              ; пока слово ≠ 0 (HALT = 0 — конец)
        RET
```

Шаблон кода заканчивается на `HALT`, за которым идут данные, не предназначенные для копирования.

### Определение модели БК (0010 vs 0011)

Биты 8–15 регистра 177716 содержат 200₈ на БК 0010 и 0 на БК 0011:

```asm
        CMPB @#177717, #200     ; SysReg+1: 200=БК0010, 0=БК0011/0011М
        BEQ  BK0010
        ; иначе — БК 0011
```

### Определение ROM/RAM через вектор HALT

Чтобы проверить, является ли адрес ОЗУ или ПЗУ, без риска зависнуть: временно ставится обработчик вектора HALT (адрес 4), затем делается запись. Если адрес — ПЗУ, запись вызовет ловушку; обработчик очищает стек и продолжает:

```asm
        MOV  @#4, -(SP)         ; сохранить оригинальный вектор HALT
        MOV  #ROM1, @#4         ; временный обработчик
        MOV  (R5), (R5)         ; попытка записи: ОЗУ — OK, ПЗУ — HALT
        BIS  #FLAG, R0          ; сюда попадём только если ОЗУ
        BR   ROM2
ROM1:   CMP  (SP)+, (SP)+       ; SP += 4: убрать фрейм прерывания (PSW + PC)
ROM2:   MOV  (SP)+, @#4         ; восстановить вектор HALT
```

### Страницы памяти БК 0011 — именованные константы и комбинирование

Удобный способ задавать состояние регистра страниц через именованные биты:

```asm
Lo  = 10000     ; сдвиг для битов страницы данных
Hi  = 400       ; сдвиг для битов страницы стека/экрана

p1  = 0b1000    ; страница 1
p3  = 0b1011    ; страница 3
DOS = 0b1100    ; страница DOS

        MOV  #p1*Lo + DOS*Hi, @#SysReg   ; страница 1 + DOS в старших битах
```

### CLR -(R4) — очистка экрана с преддекрементом сверху вниз

Альтернатива очистке снизу вверх. R4 указывает за конец видеопамяти, `CLR -(R4)` сначала декрементирует, потом очищает:

```asm
        MOV  #100000, R4    ; адрес после конца видеопамяти
        MOV  #20000, R5     ; 020000₈ = 8192 слова = 16 КБ
1:      CLR  -(R4)          ; R4 -= 2, потом CLR: от 077776 до 040000
        SOB  R5, 1
```

После цикла R4 = 040000 (начало экрана) — готов к дальнейшему использованию.

### COM #0 — двоичный переключатель в потоке команд

`COM` инвертирует все биты. Применённый к встроенному операнду `#0`, чередует значение между 0 и 177777. `BPL`/`BMI` затем выбирает одну из двух ветвей:

```asm
        MOV  #Frame1, R1    ; умолчание — кадр 1
        COM  #0             ; переключить: 0→177777 (N=1) или 177777→0 (N=0)
        BPL  1              ; если N=0 (значение=0) — остаться на Frame1
        MOV  #Frame2, R1    ; если N=1 (значение=177777) — взять Frame2
1:      ; продолжить с R1 = Frame1 или Frame2
```

Чередование без отдельной переменной и без ветвлений в основном пути.

### .repeat — развёртка цикла директивой PDPy11

Директива `.repeat N { ... }` генерирует N копий блока инструкций на этапе компиляции:

```asm
        .repeat X/8.
        {
            MOV  (R1)+, (R2)+   ; скопировать слово, оба указателя вперёд
        }
```

Результат: X/8 инструкций MOV подряд — без накладных расходов SOB и без регистра-счётчика.

### MOV #addr,(SP) / RTI — перехват возврата из прерывания

Внутри обработчика прерывания можно подменить адрес возврата на стеке и уйти в другую точку программы, а не туда, откуда пришло прерывание:

```asm
Keyb:   MOV  #Draw, (SP)    ; подменить адрес возврата
        RTI                  ; выйти не в прерванный код, а в Draw
```

Применяется для перезапуска главного цикла по нажатию клавиши без лишних флагов.

### Синхронизация с дисплеем через таймер

Ожидание нужной фазы разворта: таймер перезапускается, цикл ждёт пока счётчик не снизится до порогового значения:

```asm
        MOV  #1, @#TIMER        ; остановить и сбросить таймер (177712)
        MOV  #TIMER-4, R4       ; R4 → регистр предустановки (177706)
        MOV  #Refresh, (R4)+    ; загрузить начальное значение; R4 → счётчик (177710)
        MOV  #20, @#TIMER       ; запустить таймер

        MOV  #2, R5
Loop:   CMP  (R4), R5           ; счётчик > 2?
        BGT  Loop               ; ждать, пока не досчитает до 2
```

`TIMER-4` = 177706 (предустановка), после `(R4)+` — R4 = 177710 (счётчик).

### ROR R3 / RORB (R2) — распределение битов по плоскостям

Каждые четыре `ROR/RORB` распаковывают один байт таблицы T по битовым плоскостям в памяти. ROR выдвигает бит из R3 в флаг C, RORB заносит его в байт экрана:

```asm
        MOVB T0(R3), R3     ; взять байт из таблицы цветов
        ROR  R3             ; бит 0 → C
        RORB (R2)           ; C → старший бит (R2), нижняя плоскость
        ROR  R3             ; бит 1 → C
        RORB (R2)           ; C → старший бит (R2)
        ROR  R3             ; бит 2 → C
        RORB Size(R2)       ; C → верхняя плоскость (смещение Size)
        ROR  R3             ; бит 3 → C
        RORB Size(R2)       ; C → верхняя плоскость
```

Два кадра (Lion1 / Lion2) формируются из разных таблиц (T0/T1) и чередуются — получается временно́е дизеринг: 4 физических цвета дают визуальное ощущение большей палитры.

### Автозапуск через перезапись стека

Программы загружаются с адреса 1000₈; диапазон 760–1000₈ — стек ОС. Если загрузить программу с адреса 760₈, она перезаписывает стек адресом `START`. ОС, возвращаясь из загрузчика через `RET`, снимает со стека `START` и прыгает прямо в программу.

```asm
    .LINK 760
    .WORD START,START,START,START,START,START,START,START

BEGIN:  ; ... распаковщик или инициализация ...

START:  MOV  #1000, SP      ; восстановить SP в начало стека
        EMT  14             ; инициализация дисплея
        ; ... основная программа ...
```

Восемь копий `START` покрывают весь диапазон 760–777₈ — куда бы SP ни указывал при возврате ОС, он найдёт нужный адрес.

### MOV PC, Rn — позиционно-независимый расчёт адреса

Когда код перемещается в другое место (например, в старшее ОЗУ), абсолютные адреса ломаются. `MOV PC, Rn` фиксирует текущий PC, а затем к нему добавляется расстояние до нужной метки:

```asm
        MOV  PC, R1
M1:     ADD  #TARGET-M1, R1     ; R1 = адрес TARGET, независимо от адреса загрузки
```

При исполнении `MOV PC, R1` PC уже указывает на следующую инструкцию (метка `M1`), поэтому `TARGET - M1` — это точный байтовый офсет от M1 до TARGET.

### CLRB / SWAB / ASR — компактное деление через манипуляцию байтами

Быстрое целочисленное деление без цикла: обнулить младший байт, поменять байты местами, сдвинуть — получается сдвиг вправо на 9 бит (деление на ~512):

```asm
        MOV  R2, R1
        CLRB R1         ; обнулить младший байт: R1 = R2 & 0xFF00
        SWAB R1         ; поменять байты: R1 = R2 >> 8
        ASR  R1         ; сдвиг: R1 = R2 >> 9  ≈  R2 / 512
```

Аналогично можно получить R2 >> 8 (только CLRB+SWAB, без ASR).

### Pack34 — встроенный распаковщик (17 слов)

Компактный LZ-распаковщик. Данные читаются справа налево (с конца буфера). Каждый блок: байт-заголовок, затем данные.

- **Заголовок ≥ 0** (0–127): N слов хранится как есть — скопировать N слов.
- **Заголовок < 0** (128–255): ссылка — скопировать 1 слово из уже распакованных данных со смещением `(-заголовок) * 2` байт назад.
- **Заголовок = 0**: конец данных.

```asm
BEGIN:  MOV  #ENDPACKED, R1    ; конец упакованных данных
        MOV  #RUN, R2          ; конец выходного буфера
UNPACK: MOVB -(R1), R0
        BMI  CLONE             ; < 0 → ссылка
        BEQ  RUN               ; = 0 → конец
COPY:   MOVB -(R1), -(R2)      ; скопировать N слов как есть
        MOVB -(R1), -(R2)
        SOB  R0, COPY
        BR   UNPACK
CLONE:  ASL  R0                ; смещение в байтах
        MOV  R2, R3
        SUB  R0, R3            ; R3 → источник
        MOV  -(R3), -(R2)      ; скопировать одно слово
        BR   UNPACK
        .WORD 0                ; маркер конца
RUN:
```

### MOV #label,@#4 — охрана опциональной аппаратуры через вектор HALT

Перед обращением к регистрам, которых может не быть (SMK, страницы БК0011М), устанавливается вектор HALT на следующий безопасный блок. Если регистр не существует → шинная ошибка → HALT → прыжок на этот блок. Если регистр есть — код выполняется штатно и попадает туда же по fallthrough:

```asm
        MOV  #SAFE, @#4         ; если авария — прыгнуть на SAFE
        MOV  #6, @#MEMPAG       ; попытка включить SMK
        MOV  #60, @#MEMPAG      ; если SMK нет → шинная ошибка → @#4 → SAFE
        CLR  @#MEMPAG
        ; ... дальнейшая инициализация SMK ...
SAFE:   ; продолжение, работает с SMK или без него
```

Паттерн повторяется для каждой «необязательной» инициализации — каждый раз `@#4` перенастраивается на новый адрес обхода.

### XOR #1400,opcode — переключение между парами ветвлений

В PDP-11 коды BR=000400₈ и BNE=001000₈ отличаются ровно на 1400₈ (XOR старших байт: 01₈ XOR 03₈ = 02₈, но на уровне слова XOR = 1400₈). `XOR #1400` за одну инструкцию переключает одно в другое:

```asm
MARK:   BNE  LOOP           ; изначально — BNE
        ...
        MOV  #1400, R1
        XOR  R1, MARK       ; MARK становится BR LOOP (и обратно при следующем вызове)
```

Аналогично переключаются любые пары ветвлений с XOR-расстоянием 1400₈: BR↔BNE, BEQ↔BGE и т.п. Перед применением убедиться, что смещение перехода не затрагивает изменяемые биты.

### MULEMU — умножение 16×16 со знаком через сдвиг-и-сложение

Реализует `R0 = R1 × R2` с результатом в формате фиксированной точки (3 бита целой части, 13 дробных). Использует алгоритм двоичного умножения без аппаратных команд MUL:

```asm
; Вход: R1, R2 — сомножители (16-бит, со знаком)
; Выход: R0 — произведение в фиксированной точке (биты 15:13 — целая часть)
; Портит: R3, R4, R5
MULEMU: CLR  R4              ; старшее слово аккумулятора
        CLR  R3              ; знак результата
        CLR  R5
        CLR  R0              ; R0:R5 = 0 (аккумулятор 32 бит)
        TST  R2
        BEQ  7               ; если R2=0 — конец
        BPL  1
            NEG  R2
            INC  R3          ; запомнить смену знака
1:      TST  R1
        BPL  2
            NEG  R1
            DEC  R3          ; знаки компенсируются
2:      ASR  R2              ; сдвинуть множитель
        BEQ  4               ; последний бит
        BCC  3               ; бит = 0
            ADD  R1, R5
            ADC  R0
            ADD  R4, R0      ; добавить R4:R1 к аккумулятору
3:      ASL  R1              ; сдвинуть множимое
        ROL  R4
        BR   2
4:      BCC  5
            ADD  R1, R5
            ADC  R0
            ADD  R4, R0
5:      ROL  R5              ; извлечь 3 бита целой части
        ROL  R0
        ROL  R5
        ROL  R0
        ROL  R5
        ROL  R0
        ROL  R5
        ADC  R0
        TST  R3              ; применить знак
        BEQ  7
            COM  R0
            NEG  R5
7:      RET
```

### Трёхканальный цвет на БК0011М (RGB через три строки)

На БК0011М цветной режим адресует три плоскости через смещения 0, 100₈ и 200₈ от базового адреса пикселя. Запись R/G/B в три соседних байт-адреса:

```asm
        ; R1=красный байт, R2=зелёный байт, R3=синий байт
        ; R5 = адрес пикселя на экране
        MOVB R1, (R5)       ; плоскость R (красный)
        MOVB R2, 100(R5)    ; плоскость G (зелёный, смещение 64₁₀)
        MOVB R3, 200(R5)    ; плоскость B (синий, смещение 128₁₀)
```

### Спрайты как бинарные литералы прямо в коде

Каждая строка спрайта — одно слово `.WORD 0b...`. Двоичная запись делает пиксельный рисунок визуально читаемым прямо в исходнике:

```asm
Sprite1:    .WORD 0b0100000000000011
            .WORD 0b0000000000001101
            .WORD 0b0000000000110100
            .WORD 0b0000000011010000
            .WORD 0b0000001101000000
            .WORD 0b0000110100000000
            .WORD 0b0011010000000000
            .WORD 0b1101000000000000
```

В Ч/Б режиме 512×256: каждый бит = один пиксель, 16 пикселей на слово, строка = 32 слова. В цветном режиме 256×256: каждые 2 бита = один пиксель, 8 пикселей на слово, строка = 32 слова (64 байта).

**Цветной режим — раскладка пикселей в слове (packed, не planar):**
Пиксели упакованы последовательно парами битов: пиксель 0 → биты 0–1, пиксель 1 → биты 2–3, ..., пиксель 7 → биты 14–15. Это **не** разделение на байтовые плоскости — оба бита цвета одного пикселя **соседние**.

Цвета: 0=чёрный, 1=цвет A, 2=цвет B, 3=цвет C (обычно красный на стандартном ТВ).

Адрес слова и маска пикселя (X, Y от 0 до 255):

```asm
; R0 = адрес слова = VRAM + Y*64 + floor(X/8)*2
; R1 = маска цвета 3 (оба бита = 1) для пикселя X mod 8

CALCPIX:
        MOV R5, R0              ; Y
        ASL R0
        ASL R0
        ASL R0
        ASL R0
        ASL R0
        ASL R0                  ; R0 = Y × 64
        MOV R4, R1              ; X
        ASR R1
        ASR R1
        BIC #1, R1              ; R1 = floor(X/8) × 2
        ADD R1, R0
        ADD #040000, R0         ; адрес слова в VRAM
        MOV R4, R1
        BIC #177770, R1         ; R1 = X mod 8
        ASL R1                  ; × 2 → индекс в таблице
        MOV BITMASK(R1), R1
        RET

; Маски для цвета 3: два соседних бита (11 binary) в нужной позиции
; n=0: 3<<0=000003, n=1: 3<<2=000014, ..., n=7: 3<<14=140000
BITMASK:
        .WORD 000003, 000014, 000060, 000300
        .WORD 001400, 006000, 030000, 140000
```

Включение цветного режима: `MOVB #377, @#000040` (PRCW).

В буфере хранится **конечный** указатель `Sprite+size` (адрес байта после спрайта). При рисовании от него вычитается строковый офсет, что позволяет индексировать строки простым вычитанием:

```asm
; Buffer хранит: Sprite1+16, Sprite2+16, ...  (16 = 8 слов × 2 байта)
; R2 = строковый офсет (от 18 до 0, шаг -2)
        MOV  (R3)+, R1      ; R1 = Sprite+16 (конечный указатель)
        SUB  R2, R1         ; R1 → нужная строка спрайта
        MOV  (R1), (R5)+    ; вывести слово на экран
```

### Установка палитры БК0011М с защитой для БК0010

На БК0010 регистр 177662 — клавиатурный (только чтение), запись вызывает ошибку шины → HALT. Паттерн защиты: установить `@#4` на обработчик для БК0010 до записи в палитру:

```asm
        MOV  #BK0010, @#4           ; если HALT — прыгнуть сюда
        MOV  #42000, @#PALETT       ; БК0011М: установить палитру 4
        MOV  #16000, @#MEMORY       ; БК0011М: страница экрана
        MOV  #640., @#TIMER-4       ; БК0011М: значение таймера
        MOV  #240, COLOR            ; заменить ветвление на NOP (240₈ = NOP)
        BR   BEGIN                  ; БК0011М: пропустить обработчик

BK0010: CMP  (SP)+, (SP)+          ; убрать фрейм прерывания (SP += 4)
        MOV  #480., @#TIMER-4       ; БК0010: своё значение таймера
BEGIN:  ; общий код для обеих моделей
```

`CMP (SP)+,(SP)+` — два авто-инкрементных чтения без сохранения результата: SP += 4, что убирает фрейм прерывания (PC + PSW), оставленный на стеке вектором HALT.

### MFPS / MTPS — сохранение и восстановление PSW через стек

`MFPS` копирует слово состояния процессора (PSW) в операнд, `MTPS` — наоборот. Через стек: аналог PUSH/POP для регистра флагов:

```asm
        MFPS -(SP)      ; сохранить PSW (флаги + приоритет прерываний)
        ; ... критическая секция ...
        MTPS (SP)+      ; восстановить PSW
```

Используется когда нужно временно менять приоритет прерываний и гарантированно вернуть старое значение.

### Таймер как источник энтропии в генераторе случайных чисел

Добавление текущего значения счётчика таймера к seed'у делает последовательность непредсказуемой при разных запусках:

```asm
        ADD  @#TIMER-2, R1      ; TIMER-2 = 177710 (счётчик таймера)
```

`TIMER-2` = 177710₈ — регистр текущего значения счётчика. Его содержимое в момент обращения зависит от точного времени запуска — хороший источник энтропии.

### MOV #NOP, label — замена инструкции на NOP

```asm
        MOV  #240, COLOR    ; 240₈ = 000240₈ = NOP; перезаписать BR/BNE на NOP
```

### Данные сразу после BR — переменные в потоке команд без регистра

`BR` пропускает произвольное число байт. Несколько `.WORD` после `BR Begin` — компактная замена отдельному блоку переменных:

```asm
Speed:  BR   Begin          ; пропустить встроенные переменные
        .WORD 36543, 1321   ; timer2, timer1 — доступны как Speed+2, Speed+4
Accums: .WORD 0, 0, 0       ; дальше — накопители
Begin:  ; ... код начинается здесь ...
```

Метка `Speed` указывает одновременно на `BR` и служит базой для доступа к переменным по смещению (`Speed+2`, `Speed+4` и т.д.).

### Клонирование полупериода синуса в полную таблицу

Хранить нужно только первую четверть или половину периода. Вторая половина достраивается в обратном порядке в памяти прямо перед запуском:

```asm
; Tabl: 32 байта четверти синуса (63..1)
; После клонирования: Tabl[0..31] + Tabl[63..32] = полный полупериод
        MOV  #Tabl+32., R1      ; R1 → куда писать вторую половину
        MOV  #32., R2
1:      MOVB Tabl-1(R2), (R1)+ ; Tabl+31, Tabl+30, ..., Tabl+0
        SOB  R2, 1
; Итого 64 байта: нарастание (1→63) и убывание (63→1)
```

`Tabl-1(R2)` при R2=32..1 даёт индексы 31..0 — копирование в обратном порядке.

### Очистка памяти до конца видеоОЗУ через знаковый флаг

Продолжение после клонирования таблицы — R1 уже указывает на область после неё. Цикл чистит всё до адреса 077777 (при 100000 старший бит = 1, TST устанавливает N=1, BPL не ветвится):

```asm
2:      CLR  (R1)+
        TST  R1
        BPL  2          ; пока R1 < 0100000 (бит 15 = 0)
```

Очищает пользовательское ОЗУ выше программы и весь экран за один цикл без знания точных границ.

### XOR #100, opcode — переключение INCB ↔ DECB

`INCB (R3)` = 005213₈, `DECB (R3)` = 005313₈. Разница = 0100₈ (бит 6). `XOR #100` за одну инструкцию переключает одно в другое:

```asm
Direct: INCB (R3)           ; изначально INCB (код 5213₈)
        BNE  1
            XOR  R0, Direct ; R0=#100: INCB→DECB или DECB→INCB (код 5313₈)
1:
```

Общий принцип: любые две инструкции, отличающиеся ровно на одну битовую маску, переключаются через `XOR #маска, label`.

### MOV (R3)+,(R3) — копирование слова в следующую ячейку

Читает слово по R3, инкрементирует R3 на 2, записывает то же слово уже по новому R3 — то есть копирует [R3] в [R3+2]:

```asm
        MOV  (R3)+, (R3)    ; [R3+2] = [R3],  R3 += 2
        MOV  (R3)+, (R3)    ; [R3+4] = [R3+2], R3 += 2
```

Цепочка из двух таких инструкций передаёт значение через два регистровых слова без промежуточного регистра.

### Sin — компактный табличный синус (4 инструкции)

Индекс = младшие 6 бит угла (0–63), таблица — 64 байта:

```asm
; Вход: R4 = угол (только биты 5:0 значимы)
; Выход: R5 = sin(R4), диапазон 0..63
Sin:    MOV  R4, R5
        BIC  #177700, R5        ; R5 = R4 & 63 (маска 6 бит)
        MOVB Tabl(R5), R5       ; табличный lookup
        RET
```

Для косинуса: `ADD #Angle, R4` перед вызовом (`Angle = 16` для сдвига на четверть периода из 64 шагов).

### EMT 30 — рисование пикселя (только БК0010)

`EMT 30` рисует точку через обработчик в ПЗУ БК0010 (адрес 100112). На БК0011М ПЗУ другое — EMT 30 делает там что-то иное или ломается. **Использовать только в программах, предназначенных исключительно для БК0010.**

```asm
        EMT  14             ; инициализация экрана
        MOV  #233, R0
        EMT  16             ; переключить в режим 256×256 (код 233₈)

        ; рисование точки:
        MOV  #X, R1         ; X-координата
        MOV  #Y, R2         ; Y-координата
        MOV  #1, R0         ; 1=нарисовать, 0=стереть (для некоторых вариантов)
        EMT  30             ; нарисовать точку
```

Для установки цвета перед рисованием — отправить код цвета через `EMT 16`:
```asm
        MOV  #COLOR_CODE, R0
        EMT  16
```

### 32-битный LFSR через ASL/ROL

Сдвиговый регистр с линейной обратной связью для 32-битных псевдослучайных чисел. Старшее слово — R5, младшее — R0. Полином 0x04C11DB7:

```asm
        ASL  R0             ; сдвинуть 32-битное значение R5:R0 влево
        ROL  R5             ; бит 31 → флаг C
        BCC  1              ; если бит 31 был 0 — не XOR
            XOR  #04301, R5 ; XOR с 0x04C1 (старший полуслово)
            XOR  #16667, R0 ; XOR с 0x1DB7 (младший полуслово, 16667₈=0xDB7... )
1:      ; следующая итерация
```

Инициализация: `R5 = старшее слово seed`, `R0 = младшее слово seed`.

### MOV Rn, #0 — запись значения в собственный операнд

`MOV R0, #0` записывает R0 в слово с непосредственным операндом инструкции. Хранит «переменную» прямо в потоке команд для последующего чтения по метке:

```asm
DIR:    MOV  R0, #0         ; записать R0 в DIR+2 (вместо #0)
        ; позже:
        BITB #2, DIR+2      ; проверить бит 1 сохранённого значения
        TSTB DIR+2          ; проверить знак
```

Отличается от `MOV (PC)+, Rn / .WORD`: здесь данные пишутся «внутрь» инструкции, а не читаются из неё.

### BEQ label+2 / обнулённый счётчик как HALT

Когда счётчик-операнд достигает нуля, прыжок на него исполняет нулевое слово как HALT — без отдельной инструкции остановки:

```asm
LOOP:   MOV  #2048., R3     ; LOOP+2 = встроенный счётчик итераций
        SUB  #32., LOOP+2   ; уменьшить на 32 каждую итерацию
        BEQ  LOOP+2         ; если 0 — прыгнуть на LOOP+2, где лежит 0 = HALT
        ; ... тело цикла ...
        BR   LOOP
```

Цикл выполняется `2048/32 = 64` раза, затем автоматически останавливается.

### BIC #100200, word — маскирование обоих байт слова одновременно

`BIC #100200` очищает бит 7 в старшем байте (100₈ = 0x80) и бит 7 в младшем байте (0200₈ = 0x80) за одну инструкцию — ограничивает обе координаты диапазоном 0–127:

```asm
        BIC  #100200, BXBY  ; BX &= 0x7F, BY &= 0x7F  (оба байта в одном слове)
```

### Установка Монитора-11 и BK0011M-специфичные EMT

**Монитор** (мониторная система) — программы, зашитые в ПЗУ компьютера. На БК0010 и БК0011М разные ПЗУ → разные EMT-обработчики. Перед использованием БК0011М-специфичных EMT нужно установить вектор EMT (адрес 030) на адрес диспетчера Монитора-11:

```asm
        MOV  #152112, @#30  ; установить обработчик EMT Монитора-11 (БК0011М)
        EMT  0              ; инициализация, режим 256 пикселей в строке
```

**Дополнительные EMT-функции Монитора-11 (только БК0011М):**

| EMT | Функция | Вход |
|-----|---------|------|
| `EMT 0` | Инициализация, режим 256 пикселей | — |
| `EMT 56` | Установка экранов (отображаемый / рабочий) | R0: конфиг |
| `EMT 66` | Нарисовать точку | — |
| `EMT 77` | Нарисовать дугу / окружность | R0: указатель на параметры |
| `EMT 100` | Заливка (flood fill) | — |

**Двухэкранный режим** (отображение на одном, рисование на другом):
```asm
        MOV  #400, R0
        EMT  56             ; показывать экран 0, рисовать на экране 1
```

### ADD #1, label+N — самомодифицирующийся указатель в таблицу

Продвижение встроенного операнда `MOVB @#Tabl+offset, Rn` на 1 байт каждую итерацию — аналог `INC Rptr`, но без расхода регистра:

```asm
L2:     ADD  #1, L2+10          ; L2+10 = адрес в MOVB ниже (10 байт вперёд)
        MOVB @#SINTBL+20., R5   ; SINTBL+20 будет меняться: +21, +22, ...
        BNE  1
            NEG  L2+2           ; развернуть направление (шаг: +1 → -1)
```

`ADD #1, L2+10` инкрементирует непосредственный операнд `MOVB`, увеличивая адрес на 1 при каждом вызове. `NEG L2+2` меняет знак шага `#1` в `ADD`, разворачивая направление.

### NEG label+2 — разворот направления через отрицание шага

`ADD #N, Rn` превращается в `ADD #-N, Rn` (= вычитание) через `NEG` встроенного операнда. Одна инструкция меняет направление движения:

```asm
DIR1:   ADD  #4, R2         ; шаг вправо
        ; ...
        NEG  DIR1+2         ; теперь ADD #-4, R2 — шаг влево
        NEG  DIR1+2         ; обратно к +4
```

Аналогично: `NEG L1+2` меняет направление обхода таблицы спрайтов.

### Двойной WAIT — ожидание двух кадров

Два `WAIT` подряд: первый синхронизируется с ближайшим прерыванием, второй — со следующим. Применяется для пропуска кадра или точного контроля тайминга:

```asm
        WAIT    ; синхронизация с V-sync
        WAIT    ; пропустить ещё один кадр
        MOV  R5, @#SCROLL   ; обновить прокрутку в нужный момент
```

### Самомодифицирующийся код — стандартная техника на БК

Изменение собственных инструкций во время выполнения — **обычная и поощряемая практика** на БК0010/0011М. Не запрещена, не считается хаком. Основная причина: экономия размера программы и регистров.

Накопленные паттерны (встречаются во всех примерах выше):

| Паттерн | Эффект |
|---------|--------|
| `SUB #N, #0` | счётчик-таймер без переменной |
| `ADD #N, #0` | накопитель в потоке команд |
| `INC #val` / `DEC #val` | инкремент встроенного операнда |
| `NEG label+2` | разворот шага в `ADD #N, Rn` |
| `XOR #mask, label` | переключение между двумя опкодами |
| `MOV #val, label` | замена операнда или опкода |
| `MOV Rn, #0` | запись значения «внутрь» инструкции |
| `COM #0` | двоичный переключатель 0 ↔ 177777 |
| `ADD #1, label+N` | продвижение встроенного указателя |
| `MOV #240, label` | нейтрализация инструкции (NOP) |

При написании программ для БК — активно использовать самомодификацию для сокращения размера.

### Многофайловая структура проекта (.include / .extern)

PDPy11 поддерживает сборку из нескольких файлов. Главный файл включает остальные через `.include`, а символы из включаемых файлов объявляются через `.extern`:

```asm
; main.mac
.extern DrawPlayer, MovePlayer, InitPlayer

        .include "player.mac"   ; подключает player.mac в этом месте

FREE:
.END
```

Директива `.extern sym1, sym2` сообщает ассемблеру, что символы будут определены в другом месте (в подключаемом файле). Без `.extern` ассемблер выдаст ошибку «неизвестный символ» при первом проходе, если символ используется до его определения через `.include`.

`make_bin "filename.bin"` в начале файла задаёт имя выходного бинарника явно (иначе берётся имя исходника):

```asm
make_bin "pong.bin"
```

### Таблица переходов (dispatch table) — CALL @JUMP-2(R0)

Косвенный вызов через таблицу адресов. R0 содержит индекс × 2, таблица начинается с `JUMP`:

```asm
        CALL @JUMP-2(R0)        ; R0=2 → JUMP[0], R0=4 → JUMP[1], ...
        ...
JUMP:   .WORD Proc1, Proc2, Proc3, Proc4
```

Смещение `-2` компенсирует то, что индексация с 2 (минимальное ненулевое чётное R0). Аналогично используется `CALL @(R0)` для прямого вызова адреса, хранящегося в регистре:

```asm
        MOV #DrawSprite, R0
        CALL @(R0)              ; вызов по адресу в R0
```

### Сохранение и восстановление вектора STOP (самомодификация стека)

Стандартный паттерн перехвата STOP/HALT и чистого выхода из программы:

```asm
Start:  MOV @#4, EXIT+6         ; сохранить старый вектор STOP (PC-часть)
        MOV @#6, EXIT+10        ; сохранить старый вектор STOP (PSW-часть)
        MOV #StopHandler, @#4   ; установить свой обработчик
        MOV #340, @#6           ; приоритет 7 (запрет прерываний)
        MOV SP, EXIT+2          ; сохранить стек (для восстановления SP при выходе)
        ...

StopHandler:                    ; STOP нажат — выходим
EXIT:   MOV #0, SP              ; восстановить SP (0 заменяется на реальный SP при старте)
        MOV #0, @#4             ; восстановить вектор STOP (0 → реальный адрес)
        MOV #0, @#6             ; восстановить PSW вектора STOP
        RET
```

`MOV SP, EXIT+2` в момент старта записывает текущее значение SP прямо в операнд инструкции `MOV #0, SP` в процедуре выхода — классическая самомодификация для хранения контекста без отдельной переменной.

### .WORD HALT как разделитель в таблице данных

`HALT` (код `0`) используется как терминатор или разделитель между двумя группами данных в одной таблице:

```asm
; Таблица кодов управления: сначала коды джойстика, HALT-разделитель, затем коды клавиатуры
CodesJ: .WORD 10, 2, 1, 4, 40, 100
        .WORD HALT              ; разделитель (HALT = 0)
CodesK: .WORD 10, 31, 32, 33, 40, 40

; Использование: если R1 < #CodesK, это джойстик; иначе — клавиатура
```

Поскольку `HALT` = 0 (нулевое слово), он одновременно служит и признаком конца первой группы, и разделителем между двумя таблицами в смежной памяти.

### Встроенные семена (inline seed)

Инлайн-вариант генератора случайных чисел: семена хранятся прямо в потоке команд как операнды `MOV (PC)+, Rn`:

```asm
RANDOM: MOV (PC)+, R3           ; R3 = текущее семя 1
RND1:   .WORD 1                 ; начальное значение семени 1
        MOV (PC)+, R2           ; R2 = текущее семя 2
RND2:   .WORD 1                 ; начальное значение семени 2
        ; ... PRNG вычисление, обновление R3 и R2 ...
        MOV R3, RND1            ; записать новое семя 1 обратно
        MOV R2, RND2            ; записать новое семя 2 обратно
        RET
```

`MOV (PC)+, Rn` читает следующее слово как непосредственное значение (режим адресации «непосредственный»). Метка `.WORD` сразу после — это и операнд инструкции, и именованная ячейка памяти для последующей записи нового семени.

### Inline-константа внутри подпрограммы

Константа может быть определена через `=` прямо внутри тела процедуры (не только в заголовке файла):

```asm
DrawPause:
PausePosition = 52.*100+40000   ; вычисляется ассемблером, не занимает памяти
        MOV #PausePosition, R1
        ...
```

`PausePosition` — символическая константа ассемблера (не ячейка памяти). Может определяться в любом месте файла, в том числе внутри процедуры, для улучшения читаемости.

### 3-канальный синтез звука на COVOX (ADD + carry + XOR)

Программный генератор трёх квадратных волн через порт COVOX (177714). Принцип: для каждого канала накапливается счётчик командой `ADD #freq, #acc`; флаг переноса (C) означает «полупериод закончен» — тогда уровень канала переключается через `XOR R4, Rn`. Три канала суммируются и записываются в порт:

```asm
        MOV #50120, R4          ; маска громкости/стерео (2 байта: левый+правый)
        MOV #Tempo, R0          ; количество итераций на одну строку ноты

NOTE1:  ADD #0, #0              ; #0 заменяется на частоту ноты (самомодификация)
        BCC 1                   ; carry=0: полупериод ещё не завершён
        XOR R4, R1              ; carry=1: переключить уровень канала 1
        BR NOTE2
1:      CMP R1, R1              ; NOP с нужным размером (для выравнивания времени обеих ветвей)
        BR NOTE2

NOTE2:  ADD #0, #0
        BCC 1
        XOR R4, R2
        BR NOTE3
1:      CMP R2, R2
        BR NOTE3

NOTE3:  ADD #0, #0
        BCC 1
        XOR R4, R3
        MOV R1, R5              ; микшировать: R5 = R1 + R2 + R3
        ADD R2, R5
        ADD R3, R5
        MOV R5, @#177714        ; вывод в COVOX
        SOB R0, NOTE1
        BR ROW
1:      CMP R3, R3
        MOV R1, R5
        ADD R2, R5
        ADD R3, R5
        MOV R5, @#177714
        SOB R0, NOTE1
        BR ROW
```

**Ключевые детали:**
- `ADD #freq, #acc` — оба операнда немедленные; само накопление хранится во втором `#0` (самомодификация: `NOTE1+2` содержит накопитель, `NOTE1+4` — частоту? Нет — оба `#0` — это _одна_ инструкция `ADD #freq, #acc`, где `freq` загружается из данных ноты, а `#acc` — встроенный аккумулятор, который ADD изменяет)
- Ветви `BCC/BR` и `CMP Rn,Rn` симметричны по длине (16 тактов) — тайминг обеих ветвей одинаков, что критично для точной частоты
- `XOR R4, Rn`: R4 = `050120` — слово с двумя разными байтами для разных каналов (стерео-панорамирование через COVOX)
- `SOB R0, NOTE1` — цикл на R0 итераций; R0 = Tempo определяет длительность ноты

Загрузка частот нот (самомодификация перед строкой):

```asm
ROW:    MOV #SONG, R4           ; NOTE1+2 — самомодифицирующийся указатель
        MOV (R4)+, NOTE1+2      ; частота канала 1
        MOV (R4)+, NOTE2+2      ; частота канала 2
        MOV (R4)+, NOTE3+2      ; частота канала 3
        CMP R4, #SONGEND
        BGE PLAY                ; конец — перемотать
        MOV R4, ROW+2           ; сохранить позицию в песне (самомодификация)
```

### Таблица нот: вычисление частот через полутоновые коэффициенты

Все частоты нот вычисляются ассемблером через мультипликативные коэффициенты полутонов. Базовая частота Do (C3) — константа `Q`, умноженная на `2^(n/12)` через целочисленные коэффициенты (× 1000000):

```asm
Q   = 2000.         ; Do третьей октавы (≈ 523 Гц → 2000 тактов периода)

T1  = 1059463.      ; 2^(1/12)  × 10^6
T2  = 1122462.      ; 2^(2/12)  × 10^6
T3  = 1189207.      ; ...
T4  = 1259921.
T5  = 1334840.
T6  = 1414214.
T7  = 1498307.
T8  = 1587401.
T9  = 1681793.
T10 = 1781797.
T11 = 1887748.
M   = 1000000.      ; делитель (компенсация масштаба T1..T11)

; Октавы через умножение Q на 2:
C2 = Q/2  ;  C3 = Q  ;  C4 = Q*2  ;  C5 = Q*4  ;  C6 = Q*8.  ;  C7 = Q*16.

; Ноты внутри октавы:
D3  = C3*T2/M       ; ре   третьей октавы
E3  = C3*T4/M       ; ми
F3  = C3*T5/M       ; фа
Fd3 = C3*T6/M       ; фа-диез (d = диез)
G3  = C3*T7/M       ; соль
A3  = C3*T9/M       ; ля
B3  = C3*T11/M      ; си
```

PDPy11 выполняет все умножения и деления на этапе ассемблирования — в бинарник попадают уже готовые 16-битные константы. Деление `/ M` компенсирует масштаб коэффициентов T1–T11.

**BPM и темп:**
```asm
BPM = 120.                          ; определяется в music.mac
Tempo1 = (130000.*7/6) / BPM        ; длительность нечётной строки
Tempo2 = (130000.*4/6) / BPM        ; длительность чётной строки
```

Нечётные строки длиннее чётных (7/6 vs 4/6) — создаёт ритмическую пульсацию без отдельного таймера.

### Самомодифицирующееся восстановление вектора прерывания

Сохранение и восстановление вектора клавиатуры без отдельной переменной — через запись оригинального значения прямо в тело обработчика выхода:

```asm
; При инициализации:
        MOV @#60, MusicExit+14  ; записать оригинал @#60 в операнд инструкции ниже
        MOV #MusicExit, @#60    ; установить свой обработчик
        MOV @#274, MusicExit+22 ; то же для вектора 274
        MOV #MusicExit, @#274

; Тело MusicExit (смещения в байтах от метки):
MusicExit:                      ; +0
        MTPS #340               ; +0: 2 байта
        MOV #100, @#177660      ; +2: 6 байт — заблокировать прерывания клавиатуры
        MOV #100000, @#60       ; +8: 6 байт — ← +10(oct): #100000 заменён на оригинал
        MOV #100000, @#274      ; +14: 6 байт — ← +22(oct): #100000 заменён на оригинал
        CMP (SP)+, (SP)+        ; сбросить адрес возврата и PSW с прерывания
        MOV @#177662, R0        ; прочитать клавишу (сброс буфера клавиатуры)
        RET
```

`MusicExit+14` (десятичное) = смещение к `#100000` в инструкции `MOV #100000, @#60`. При инициализации туда записывается реальный адрес из @#60 — и при выходе инструкция восстанавливает оригинальный вектор, а не фиксированную константу.

---

### CMP (SP)+,(SP)+ — сбросить два слова со стека

Используется внутри обработчика прерывания для «чистого» выхода через `RET` вместо `RTI`. Прерывание кладёт на стек PC и PSW; два `(SP)+` в операндах `CMP` снимают их без сохранения:

```asm
MusicExit:
        ; ... восстановление регистров ...
        CMP (SP)+, (SP)+        ; убрать PC и PSW прерывания со стека
        MOV @#177662, R0        ; сбросить буфер клавиатуры
        RET                     ; теперь SP указывает на адрес возврата из CALL MUSIC
```

`CMP` здесь используется только ради побочного эффекта пост-инкремента обоих операндов. Результат сравнения не важен.

### .extern all — импорт всех символов из подключаемого файла

Если подключаемый файл определяет много символов, используемых до его `.include`, можно объявить их все разом:

```asm
.extern all     ; все символы из включаемых файлов считаются объявленными
```

Обычная форма — перечисление: `.extern BPM, SONG, SONGEND`. Форма `all` — ярлык, когда символов много (например, вся таблица нот C1..B6).

## Видеорежимы

### Чёрно-белый режим (64 символа в строке)

- 1 бит на пиксель
- Разрешение: 512×256 пикселей
- Строка развёртки: 64 байта = 512 пикселей
- 1 байт = 8 пикселей

### Цветной режим (32 символа в строке)

- **2 бита на пиксель**, 4 цвета
- Разрешение: **256×256** пикселей
- Строка развёртки: 64 байта = 256 пикселей
- **1 байт = 4 пикселя** (не 8!)

Цвета: 0=чёрный, 1=цвет A, 2=цвет B, 3=цвет C. Активируется через `MOVB #377, @#000040` (PRCW) или кодом `233₈` через EMT 16.

Паттерны в файлах `palette*.raw` рассчитаны именно на 2bpp: каждый байт кодирует 4 цветных точки.

## Производительность и память

### Реальная скорость ≠ тактовая частота

Рост тактовой частоты не означает пропорционального роста производительности — узкое место на БК это **медленная память**, а не CPU.

Большинство инструкций PDP-11 обращаются к памяти несколько раз: `#immediate` — дополнительное слово в шине, `indexed(R)` — ещё одно, `MOV @#addr` — два обращения. При разгоне CPU память работает на тех же чипах → процессор вынужден ждать.

Реальные цифры из 512-байтовой демо с метаболлами (площадь окна как косвенный показатель производительности):

| Машина | Тактовая | Площадь окна | Реальный прирост |
|--------|----------|--------------|-----------------|
| БК 0010 | 3 МГц | 800 пикс. | — |
| БК 0011М | 4 МГц (+33%) | 1008 пикс. | **+26%** |
| БК 6 МГц | 6 МГц (+100%) | 1160 пикс. | **+45%** |

При удвоении тактовой реальная скорость выросла лишь на 45%.

## 512-байтовые интро

Жёсткий формат: программа целиком умещается в 512 байт. Каждые 2 байта на счету. Типичные компромиссы:

- **Убирается защита** (`MTPS #340`) ради экономии места — допустимо для демо без пользовательского ввода, неприемлемо для игры или системной программы
- **Различия между версиями** для разных платформ могут быть вызваны не архитектурными требованиями, а нехваткой байт
- Адрес загрузки `.LINK 760` с автозапуском через стек ОС

**Правило анализа:** при изучении различий между вариантами одной программы сначала проверить — это осознанный дизайн или компромисс размера.

## Алгоритм метаболлов (предвычисленный спрайт влияния)

Техника оптимизации для эффекта metaballs на медленном железе. Вместо вычисления `RADIUS/distance` для каждого пикселя в каждом кадре — одно предвычисление, потом три чтения из спрайта.

### Структура данных

```
PALET  — COLORS*2 слов: каждое слово = указатель на 5-байтовый паттерн цвета
QUAD   — таблица квадратов: QUAD[2*x] = x^2 (избегает умножения)
SQRT   — таблица: SQRT[D^2*2] ≈ RADIUS/D - 4  (слово-адресация)
CIRCLE — предвычисленный спрайт (WIDTH*2)×((HEIGT+2)*2) слов
CENTER — адрес центрального пикселя спрайта (смещение = позиция блоба)
```

### Функция влияния с отрицательным смещением

```asm
CLR R3
MOV #-4,R0
2:  INC R0
    ADD R1,R3       ; накапливаем кратные R1
    CMP R3,#RADIUS
    BLE 2           ; пока R3 ≤ RADIUS
; R0 = ceil(RADIUS/R1) - 4
```

Результат: `RADIUS/D - 4`. При `D ≈ RADIUS/4` значение обнуляется, при больших D уходит в минус. Граница метаболла — там где сумма трёх вкладов пересекает 0. **Нет явной проверки порога**, функция сама создаёт нужное поведение.

### Один спрайт — три шара

Все шары одинаковые, поэтому спрайт один. Позиция шара — смещение в спрайте от CENTER:

```asm
MOV #CENTER,R2
MOV R2,R3
SUB (R1)+,R3    ; Y-смещение шара 1 (в байтах: Y_пикс × WIDTH*4)
SUB (R1)+,R3    ; X-смещение шара 1 (в байтах: X_пикс × 2)
; R3 → точка входа в спрайт для шара 1
```

Рендер кадра — просто три параллельных чтения со сложением:

```asm
XNEXT:  MOV (R3)+,R0    ; вклад шара 1
        ADD (R4)+,R0    ; + вклад шара 2
        ADD (R5)+,R0    ; + вклад шара 3
        ASL R0          ; *2 (word-индекс в PALET)
        MOV PALET(R0),R0 ; указатель на 5-байтовый паттерн
        MOVB (R0)+,(R2)     ; строка 0
        MOVB (R0)+,100(R2)  ; строка 1 (+64 байта = +1 строка растра)
        MOVB (R0)+,200(R2)  ; строка 2
        MOVB (R0)+,300(R2)  ; строка 3
        MOVB (R0), 400(R2)  ; строка 4
        INC R2
```

Каждый «пиксель» метаболла = 1 байт (4 физических точки в цветном режиме) в ширину и 5 строк растра в высоту. Паттерн — 5 байт, один на каждую строку.

### Смещение в конце строки

```asm
ADD #500-WIDTH,R2   ; 500₈=320₁₀ байт = 5 строк растра; минус уже пройденные WIDTH байт
```

После отрисовки WIDTH пикселей в строке R2 продвинут на WIDTH байт. `ADD #320-WIDTH` доводит до следующего «текстового ряда» (5 строк растра × 64 байта = 320 байт от начала предыдущего ряда).

### PALET — таблица указателей, не цветов

```asm
; Построение: COLORS*2 слов, каждое = указатель на 5-байтовый блок
MOV R1,(R4)+        ; записать указатель
CMP R1,#PATT+175.
BGE 3               ; насыщение: все значения выше порога → один паттерн
ADD #5,R1           ; следующий паттерн (5 байт)
```

Насыщение при `PATT+175` означает: суммы выше определённого порога получают один и тот же (самый яркий) паттерн — имитация «твёрдой» поверхности внутри метаболла.

### Центрирование окна на экране

```asm
MOV #60040-(HEIGT*5/2)*100-WIDTH/2,R2
```

- `60040₈` = вертикальный и горизонтальный центр экранного ОЗУ
- `(HEIGT*5/2)*100₈` — половина высоты окна в байтах (5 строк растра × 64 байта × HEIGT/2)
- `WIDTH/2` — половина ширины в байтах

Формула одинакова во всех версиях; при изменении WIDTH и HEIGT окно автоматически остаётся по центру.

### Очистка ОЗУ и экрана одним циклом

```asm
CLR:    MOV #100000-FIN,R0
1:      CLRB FIN-1(R0)
        SOB R0,1
```

`FIN-1+R0` при R0 от `100000-FIN` до 1 проходит адреса от FIN до 077777 — весь хвост ОЗУ плюс весь экран. Два compile-time константы (FIN и 100000), один регистр.

### Данные DIRECT+BLOBS — связанные массивы через фиксированное смещение

Направления движения и координаты блобов хранятся в смежных массивах:

```asm
DIRECT: .WORD Y_dir1,X_dir1, Y_dir2,X_dir2, Y_dir3,X_dir3   ; 12 байт
BLOBS:  .WORD Y_pos1,X_pos1, Y_pos2,X_pos2, Y_pos3,X_pos3   ; смежно
```

DIRECT занимает ровно 12 байт = 14₈. Поэтому `14₈(R1)`, когда R1 указывает на любой элемент DIRECT, всегда попадает в соответствующий элемент BLOBS:

```asm
MOV #DIRECT+14,R1   ; 14₈=12₁₀ → R1 = BLOBS[0]
MOV #3,R0
1:  ADD -(R1),14(R1)    ; -(R1)→DIRECT[i], 14₈(R1)=DIRECT[i]+12=BLOBS[i]
    BGT 2
        NEG (R1)         ; отразить при выходе за 0
2:  CMP 14(R1),#WIDTH*2
    BLO 3
        NEG (R1)         ; отразить при выходе за правую границу
3:  ADD -(R1),14(R1)    ; аналогично для Y-компоненты
    ...
    SOB R0,1
```

Одна пара `ADD -(R1),14(R1)` — атомарно: декремент R1 к direction + добавление direction к position. Три блоба обновляются за один проход SOB.

Шаги движения задаются кратными размеру окна: `WIDTH*4` байт по Y (= 1 строка спрайта), `2` байта по X (= 1 пиксель). Скорость блобов в пикселях/кадр остаётся одинаковой для всех трёх версий программы, несмотря на разный WIDTH.

### Масштабирование под разные скорости CPU

Единственное отличие между версиями для БК 0010 / БК 0011М / БК 6 МГц — четыре константы в начале файла:

| Параметр | БК 0010 3 МГц | БК 0011М 4 МГц | БК 6 МГц |
|----------|--------------|----------------|---------|
| RADIUS   | 130          | 135            | 140     |
| WIDTH    | 32           | 36             | 40      |
| HEIGT    | 25           | 28             | 29      |
| SIZE     | 41           | 46             | 48      |

`SIZE = ceil(sqrt(WIDTH² + HEIGT²))` — радиус описанной окружности вокруг окна, задаёт размер таблицы SQRT. Весь остальной код идентичен.
